# `auto-docs` — what the pipeline hands AUTO, written down and derived from the code

## Summary

Andrus Giraldo asked how the pipeline sets AUTO's constants (`NTST`, `NCOL`, `IPS`,
`ICP`, `ISW`, the `EPS` tolerances) and which `PAR` slot holds what, and could not read
either off `codegen.py`. This branch answers in one guide,
[`guides/auto-pipeline.md`](../guides/auto-pipeline.md): the four generated files, the
slot table with his numbering beside ours, the base constants file, what each stage
passes on top of it, a glossary of the constants with the manual's sections, and how
to inspect a run. The grilling round of 2026-10-29 settled the rest of the branch: the
tolerances `EPSL`, `EPSU`, `EPSS` become `IsochronSettings` fields so that he can set
them to $10^{-12}$ from a config; a diagnostic dumps the generated files for a config;
a failed session keeps its directory; and two tests derive the guide's tables from the
code so that the guide cannot drift.

Irreversible in effect: the tolerance fields enter the isochron hash, so
`SHIPPED_HASHES` is repinned (`fhn` `11305875 → 1d0ffe43`, `fhn-easy`
`fb823a3f → defa5f18`) and every saved foliation is recomputed under the new names;
Joon recomputes the cluster files once this branch is pushed. Everything else is one
`git revert` away.

## Design

- **A guide, not a longer module docstring.** The slot table and the per-stage table
  are read by someone who has AUTO open and the package closed, so they live under
  `docs/guides/` with Andrus's numbering beside ours; the docstrings point there.
  Rejected: expanding `codegen.py`'s docstring, which would restate a table a reader
  of the code does not need.
- **The tables will be derived, not maintained.** A later commit asserts the slot
  table against `internal_indices(4)` and the per-stage constants against
  `Runner.constants`, so a change of either fails a test until the guide follows;
  until then the guide's frontmatter says its verification is pending.
- **The tolerances live in the constants file, not in every run's keywords.** AUTO
  reads the file on every run, so writing them there once at `auto_session` holds
  them for every stage with no change to the stages; `Runner.constants`, which the
  per-stage table derives from, therefore does not list them, and the guide says so.
  Rejected: adding them to `bvp()`, which would thread the settings into every
  stage's signature for a value that never differs between runs.
- **Flat fields on `IsochronSettings`, one container on the AUTO side.**
  `AutoTolerances` is the single conversion site into the file; the settings carry
  the three as fields because `IsochronFoliation.load` rebuilds the settings from
  flat JSON and the Hydra schema and the hash read the dataclass flat. The
  `tolerances` property is the only bridge.
- **Manual sections by title.** The glossary cites the manual's chapter and
  subsection titles (`§ NTST`), which survive a rebuild of the PDF; page and line
  numbers do not.
