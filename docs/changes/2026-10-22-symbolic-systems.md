# `symbolic-systems` — one symbolic definition per system; JAX `rhs` and AUTO-07p Fortran derived from it

## Summary

This branch is the first step of the AUTO isochron work (roadmap O7; plan `claude/isochron-auto-plan-2026-10-22` in the Project, decisions 1–6). Every system now declares its vector field once, as SymPy expressions, and the JAX `rhs`, `params()` and the AUTO-07p Fortran `RHS` with its exact Jacobian are derived from that one definition. An observed system writes a cartesian template, `_symbolic_template`; a normal form writes its field in polar coordinates, `_symbolic_template_polar`, and the cartesian template is derived from it. The Fortran is `INCLUDE`d into a generic, hand-maintained multi-segment BVP file whose parameter slots are named constants. Nothing here runs AUTO; the pipeline that does is the next branch (`auto-isochrons`, ADR-0017).

Review round 1 (2026-10-27) unified the normal forms' contract with the observed systems'. The normal forms first wrote their rates as tuples from `_symbolic_rates` or `_symbolic_rates_sq`; they now write the same `SymbolicODE` type in polar coordinates and subclass `AbstractSymbolicODE`. The even family is declared by the base class and checked when a form is created. The decisions were settled in a grilling session with Joon on 2026-10-27 and are recorded in ADR-0016; ADR-0013 and ADR-0007 are restated to match.

## Design

- **One SymPy definition per system, with both projections derived** (ADR-0016 §1). Keeping the hand-written `rhs` and generating only the Fortran was rejected, because it leaves two places to edit per system.
- **A normal form writes its polar field as a `SymbolicODE`** (ADR-0016 §2). `_symbolic_template_polar` returns the states $(r, \theta)$ and the expressions $(\dot r, \dot\theta)$, the same type that FitzHugh–Nagumo returns from `_symbolic_template`. The base class reads $\rho = \dot r / r$ and $\omega = \dot\theta$ off it, and it raises at class creation if the template does not have two states, depends on $\theta$, or has a $\dot r$ without the factor $r$. Putting $(\rho, \omega)$ into the `rhs` slot was rejected, because the slot promises a vector field. The rates tuples of the first version are superseded (ADR-0016, *Alternatives rejected*).
- **The even family is declared and checked, not written as a second hook** (ADR-0016 §2). A form joins `AbstractEvenNormalForm` by declaring it as its base class; `_compile` raises unless both rates are free of non-integer powers of $s$ after $r = \sqrt s$ is substituted. That test is stricter than evenness, and it is what the square-root-free field needs: $\cos r$ is even, but $\cos\sqrt s$ has no derivative at $s = 0$. A family detected without a declaration was rejected, because a typo that added an odd power to Bautin's $\rho$ would then change Bautin's `rhs` and drop the `r_squared` integration without an error.
- **`AbstractNormalForm` subclasses `AbstractSymbolicODE`** (ADR-0016 §2). It inherits `symbolic()` and `params()`, which removed three hand-written `params()` and the protocol `SupportsSymbolic`. Both `rhs` overrides stay: the compiled cartesian field of Winfree's form (`a = -0.25`, `w = -0.5`) has a `nan` Jacobian at the origin, where the safe-square-root `rhs` gives `[[0.25, 0.5], [-0.5, 0.25]]`.
- **One extension point, `_compile`, behind the `ABCMeta` rule** (ADR-0016 §3). `__init_subclass__` calls `_compile` when the class has no abstract methods left, computed by CPython's own rule from `ABCMeta.__new__`; each layer extends `_compile` through `super()`. The rule agrees with `__abstractmethods__` on all seven classes of the hierarchy. A separate `__init_subclass__` per layer was rejected, because it repeats the guard in three places.
- **`CompiledExpressions.from_expressions` is a classmethod.** The former free function `compile_expressions` only built the type; the free-function convention for `build_*` covers library objects built from configs, which this is not.
- **The guard is private to `symbolic.py`, not in `utils/`.** Its only purpose is the compile-once guard, and `AbstractSymbolicODE.__init_subclass__` is its only caller; `utils/` holds helpers that several packages use.
- **Every concrete class compiles `_compiled`, the normal forms included,** although their `rhs` overrides do not read it. The build keeps one invariant across the hierarchy and checks that the cartesian template translates to JAX, at the cost of one `sympy2jax` module per class at import.
- **The even family's own `log_growth_rate` and `angular_rate` were removed.** They evaluated the $s$-form at $r^2$; with both forms compiled from the same expression, they had become a second route to $\rho(r)$.
- **`params()` reads the compiled parameter names**, not `symbolic().params`, because a normal form's `symbolic()` re-derives the cartesian template with SymPy at every call, and `__repr__` calls `params()`.
- **$\rho$ is compiled in SymPy's canceled form.** `sp.cancel` also handles a $\dot r$ written expanded, such as `a*r - a*r**3`, where plain division would leave $r/r$ and a `nan` at the origin; the price is that Hopf's and Bautin's $\rho$ are compiled as expanded polynomials.
- **Parameter symbols are named after the attributes that hold their values,** which are read by `getattr` at call time. Bautin's constrained `a` and `b`, properties over `raw_a` and `raw_b`, therefore work unchanged, and `params()`, the `PAR` dict and the Fortran slot numbering share one order.
- **The Fortran is assembled by `INCLUDE`, not by a template engine** (ADR-0016 §4). The generic file stays Fortran. Line wrapping uses a leading `&` on continuations, because SymPy's own wrapper can cut `**` into `* *`.
- **Slots** (ADR-0016 §5): `PAR(1..n)` for the system and the pipeline's block after `max(n, 10)`; `NPAR = max(last, 36)`; more than ten parameters raise. `write_problem` refuses `dim ≠ 2`.
- **`constants_file` reproduces the coworker's `c.fncMultiSeg`** (NTST 300, NCOL 5, EPS 1e-10), with `NDIM`, `NPAR` and `THL` generated; run-specific constants belong to the pipeline.
- **The generic file keeps the `NDIM = 2` branches** (`PVLS`'s anchor, `STPNT`) that the plan's step 4 drops together with the Hopf path. Without a Fortran compiler in this environment, the file was changed only where the change is mechanical; the next branch, which can compile it against AUTO, makes the structural edit.
- **Round 1 lands on this branch.** `master` already contains the first commit (`6d69e47`, through PR #1), and the rewrite answers the review recorded here.

## Tests

`uv run pytest tests/test_symbolic.py tests/test_auto_codegen.py tests/test_systems.py tests/test_normal_forms.py --hypothesis-profile=dev -n 2` gives 96 passed and 4 skipped (the `f2py` tests, for lack of `gfortran`) in 210 s, against a baseline of 88 passed and 4 skipped before round 1. `test_systems.py` and `test_normal_forms.py` pass unchanged, which pins that the derived fields and hooks reproduce the former ones numerically. The whole quick suite, `uv run pytest tests -m "not slow" --hypothesis-profile=dev -n 2 -W error::SyntaxWarning`, gives 604 passed, 1 xfailed (the pinned `sinh` underflow) and 1 failed in 25 min. The failure is a crashed worker, not an assertion: worker `gw1` died while running `test_analysis_ode.py::test_floquet_functions_jit_and_vmap_over_cycles`, and the test passes when run alone (1 passed, 33 s). At the time, four JAX processes shared the sandbox's 7 GB, because the four affected files were being rerun beside the suite, so memory is the likely cause; no kernel log confirms it. CI on the pull request is the clean run. `ruff check`, `ruff format --check`, `ty check` on `systems`, `analysis/ode/auto` and `model/invertible`, `codespell`, `check_spelling.py`, `check_docstring_headers.py`, `check_references.py` and `check_md_math.py` are clean.

- `test_symbolic.py`, 36 tests. Section 1 checks the derivation. The derived `rhs` equals SymPy's own `lambdify` of the cartesian template on all seven system instances, at Hypothesis-drawn points of each basin, and `jit`, `vmap` and `jacfwd` through it agree with the symbolic Jacobian. Every normal form's `log_growth_rate` and `angular_rate`, and the even forms' `_sq` hooks, equal $\dot r / r$ and $\dot\theta$ that the test itself reads off the polar template. `params()` returns the constructor's values, constrained ones included, in the template's order. Section 2 checks the compilation. The compiled forms are class attributes of each concrete class, not dataclass fields and not pytree leaves. A class compiles only when no abstract method is left: a layer that defines the template and adds an abstract method builds nothing, and its concrete subclass, which inherits the template, builds. The cartesian conventions (parameter names, stray symbols, expression count) and the polar ones ($\theta$-dependence, the factor $r$, two states, even-family membership for an odd power and for $\cos r$) each raise `ValueError` at class creation. Each of these four polar checks was disabled in turn, and its test failed. Section 3 checks symbolically that the closed forms `h` and `Ψ` of Hopf, Bautin and Winfree satisfy `ω + h'rρ = ω₁` and `(log Ψ)' rρ = κ`, with `Ψ(1) = 0`, `Ψ'(1) = 1` and `h(1) = 0`, against the polar template's rates; the logarithmic derivative is used because `simplify` does not close the product form with Bautin's symbolic exponent `b`. Section 4 converts the derived cartesian template back to polar coordinates: for each normal form it is the polar template again, FitzHugh–Nagumo's field does not separate, and the even forms' cartesian fields are polynomial while Winfree's is not. The conversion runs `trigsimp` before `simplify`, because `simplify` alone leaves powers of $\sin\theta$ and $\cos\theta$ in Bautin's expanded field.
- `test_auto_codegen.py`, 24 tests and 4 skipped. The printed `F(i)` and `A(i,j)`, parsed back from the Fortran text into SymPy, equal the template's expressions and Jacobian at random points; every line fits `LINE_WIDTH`, and continuations are marked on both ends. The FitzHugh–Nagumo block equals the golden file `tests/golden/fitzhugh_nagumo_rhs.inc`, which is the coworker's hand-written `RHS` up to term order. The slot block for 0–10 parameters starts at 11 and is contiguous and fully named, and 11 parameters raise. The generic file references only `IP_*` slots, all declared by `indices.inc`, and has both `INCLUDE`s. `write_problem` lays down the four files, the `PAR` dict, `slot("c") == 3`, a stable source hash, and `NDIM`, `NPAR` and `THL` in the constants; Hodgkin–Huxley is refused. The four `slow` tests compile the generated `RHS` through `numpy.f2py` and compare it with `rhs` and `jacfwd(rhs)`; they are skipped without `gfortran` and have not run.

## Open issues

- The `f2py` test and the `INCLUDE` resolution inside AUTO's own build are unverified, since this environment has no `gfortran`. Both are the first thing to run on a machine with a compiler; `numpy.f2py -c` may need `meson` and `ninja` in the dev group under NumPy 2.
- `src/Isochron2PBVP` (the coworker's script, Fortran and 100 CSVs) stays in place; the next branch removes it once the pipeline reproduces its output.
- Hypothesis prints `FitzhughNagumo(_compiled=…)` in failure reports, because its pretty-printer walks `__dataclass_fields__`, which lists `ClassVar` pseudo-fields. The repository's own `__repr__` is unaffected.
- The $\theta$ check is syntactic (`.has(theta)`). A template whose expression contains $\theta$ but does not depend on it, such as $\sin^2\theta + \cos^2\theta$, is refused; simplifying first would make the check depend on SymPy's simplifier.
- `sympy2jax` emits `Mul(-1, x)` rather than a negation. The difference is numerically irrelevant, so no test checks HLO structure.
